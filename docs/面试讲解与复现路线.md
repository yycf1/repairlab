# 面试讲解与复现路线

## 项目讲解示例

“我在 mini-swe-agent 的基础循环上做了 Python 仓库诊断与修复 Agent。既可以接收缺陷，也可以只选择仓库，让模型阅读代码和项目约定、自主提出问题假设，调用工具复现，再根据结果调整计划。新增工作包括候选证据、不可事后改写的复现测试、版本绑定的提交条件和受限编辑。最终补丁在干净副本中应用，再跑外置验收、回归和同一份复现；生成的复现不冒充独立验收。界面能查看调查证据和完整行动记录。当前有自建样例的真实模型实测，外部仓库的系统评测仍待补充。”

## 需要回答的追问

1. **为什么是 Agent？** 模型选择工具动作，反馈影响后续决策；控制器和验证器是确定性程序。脚本演示自身不能证明自主决策。
2. **复用了什么？** 上游循环、消息和异常控制流；新增工具、权限、runner、验证器、服务及前端。指出 `_vendor` 和来源记录。
3. **为什么不是多 Agent？** 当前问题在反馈可靠性和验收，不在角色数量；没有实测收益前保持单 Agent。
4. **如何避免改测试作弊？** 修改权限保护测试和配置，最终 diff 二次检查，验收不在开发副本。需说明本地模式的隔离限制。
5. **如何判定修好？** 补丁能应用到干净副本，验收及回归均通过；测试覆盖有限，不能证明所有输入正确。
6. **如何控制成本？** 限步数、usage token、测试次数和命令时间，裁剪上下文；阈值检查不是精确硬限额。
7. **为何先做 Python？** 收敛执行和验证协议，其他语言通过 runner、镜像和策略扩展。
8. **上下文太长怎么办？** 保留规则和问题，每次注入当前计划，裁剪最近消息；目前没有语义代码检索。
9. **中断后怎么办？** 每步落盘检查点（循环计数、模型用量、工作流证据）与轨迹（完整对话）；带检查点的中断任务校验工作区内容摘要与检查点一致后，可从原对话现场续跑，工作区被改动则拒绝。
10. **两项目如何互补？** 文献助手覆盖检索、证据和引用；代码 Agent 覆盖行动、失败反馈、执行约束和可验证产物。

## 自己复现的顺序

先读 `agent.py` 和上游循环，跟一次 `csv-tags` 演示轨迹。再重建文件工具及 pytest runner，制造失败并解释反馈分类。之后重建验证器，提交空补丁或改测试观察拒绝原因。最后接入真实模型，逐步解释它每次看到了什么，以及控制器在哪里拦截异常。

## 下一步补充

内置样例很小。下一阶段应选择自己熟悉、依赖可控的真实 Python 仓库，固定 commit，整理公开缺陷、开发测试及独立验收。实际模型重复运行并记录成功率、回归失败、调用数、tokens 和耗时，保留失败样本；固定模型、任务和预算后再做策略对照。

先完成 Docker 实机验证，再考虑异步模型取消、执行现场恢复和第二语言 runner。相关数字和能力只在实际验证后进入简历。
