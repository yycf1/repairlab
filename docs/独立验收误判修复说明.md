# 独立验收误判修复：全跳过不等于通过

> 本文保留早期文本计数修复记录。2026-10-21 已改用结构化报告与关键清单，当前行为见 [结构化验收与关键用例](结构化验收与关键用例.md)。

日期：2026-10-13。改动聚焦最终验证器，不扩展 Agent 工具或执行环境。

## 实际问题

临时仓库中有一个源文件补丁，验收测试和回归测试分别只有一个 `pytest.skip`。原验证器的实际输出是：

```text
验收：1 skipped，exit_code=0
回归：1 skipped，exit_code=0
结果：passed=true，reason=verified
```

pytest 可以在所有测试跳过或标为预期失败时成功退出。退出码 0 说明测试进程按该运行语义正常结束，不足以说明有测试证明补丁满足要求。

## 修改

- [反馈计数](../src/repairlab/feedback.py)提供共用的 `pytest_counts`，支持 passed、failed、error/errors、skipped、xfailed 和 xpassed。
- [最终验证器](../src/repairlab/verification.py)保留退出码、超时、取消和输出限制检查，并要求验收与回归各自有至少一项 passed。
- 报告在两组执行结果中保留 `counts`。运行正常但没有通过证据时，返回 `passed=false` 和 `reason=no_passing_verification_tests`。
- 原有最终生成复现检查继续生效。没有外置验收集时，仍如实标记 `independent_acceptance=false`。

## 回归覆盖

[新增测试](../tests/test_verification.py)通过真实 pytest 子进程检查：

| 验收集 | 回归集 | 预期结果 |
| --- | --- | --- |
| 有通过测试 | 有通过测试 | 可通过 |
| 有通过及可选跳过 | 有通过测试 | 可通过 |
| 全跳过 | 有通过测试 | 拒收 |
| 有通过测试 | 全跳过 | 拒收 |
| 全跳过 | 全跳过 | 拒收 |
| 只有预期失败 | 有通过测试 | 拒收 |

另用无摘要 runner 验证无法取得通过计数时不会默认成功。上述场景均有源文件补丁，并经过真实干净副本和 Git patch 应用路径。

本轮完整回归：104 passed，175.24 秒。唯一提示为既有 FastAPI/Starlette TestClient 的 httpx 迁移弃用提示。改动文件 Ruff 检查通过；没有收费模型调用或 Docker 运行。

## 按改动学习的阅读顺序

1. 看上方误判输出：理解“进程成功”和“产物得到验证”的区别。
2. 打开 `verification.py`，沿 `verify` 找原始快照、补丁应用、验收、回归和最终判定。
3. 看新增 `counts` 与 `has_passing_checks` 如何参与最终判定；原有失败条件仍然保留。
4. 看 `test_verification.py` 的正常、混合与全跳过场景，了解如何验证修复没有破坏正常流程。

这些是阅读入口，不要求先答题或重写完整模块。

## 当前限制

计数来自 pytest 文本输出；缺少可识别的通过计数时采用拒收。它不是对测试输出真实性的完整证明，下一阶段可考虑结构化报告。

至少一项 passed 只能排除本轮复现的零通过误判，不能证明所有关键测试都执行、测试预期正确或补丁对所有输入正确。关键用例清单、必需测试缺失、独立验收来源和容器实测仍需分别验证。开发阶段的反馈分类未在本轮全面调整。
