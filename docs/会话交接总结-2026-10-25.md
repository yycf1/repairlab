## 一、项目是什么

**修码工坊 · RepairLab**——本地 Web 工作台形态的代码修复 Agent。接入一个 Python 仓库（或用内置演示夹具），描述缺陷，Agent 在**独立副本**里调查、修复、提交补丁；补丁交由 **Agent 碰不到的干净副本**重跑验收/回归测试做独立验证，通过后可一键应用回原仓库（可撤销）。

定位：**求职作品**（Agent 开发/AI 应用方向，郑州大学 AI 硕士）。项目路径 `E:\简历项目2`；简历中为"项目 2"。

核心卖点（面试口径）：
1. **门禁驱动的 Agent 循环**：20+ 个稳定短码控制门（protected_file / baseline_not_run / no_failing_evidence / tests_partial / submission_blocked…），模型想跳过"先复现再修""全量测试通过才能提交"等纪律时直接拦截，而不是事后兜底。
2. **独立验收不信 Agent 自报**：干净副本 git apply + 重跑 + 逐项核对 pytest 结构化证据；确认的复现测试作为 fail-to-pass 探针。
3. **诚实的评测**：内置自建夹具、单模型、小样本，从不冒充 SWE-bench 口径；离线 13 场景 + 真实模型 21 任务矩阵（20/21 通过，qwen3.8-max）。

- **设置拆分**：右上「⚙ 设置」= 运行设置（Docker/本地分段 + 信任勾选 + 预算步数/超时）；模型配置独立对话框；信任守卫触发时自动开运行设置并脉冲高亮勾选行
- **检查会话化**：检查环境/收集测试 → 创建历史会话（task_kind=check, status=checked）并自动跳转；preflight 事件渲染为时间线事件卡；不支持追加指令
- **会话删除**：悬停 × → 两步确认 → DELETE /api/tasks/{id}（清存储/事件/磁盘副本）；运行中拒绝
- 修复：预检明细卡死（composer 高度上限）、静态资源 no-cache、禁用光标 not-allowed、模式预填移除等
