# 自主诊断实现说明

## 目标与入口

用户选择 Python 仓库后，可以只提出“检查这个仓库”，由模型自主调查具体问题，也可以继续使用指定缺陷修复。自主入口为 `StartRequest.task_kind=inspect`，检查关注点使用可选 `issue`；为空时使用通用调查目标，不使用仓库的预存缺陷答案。首版仍依赖已经配置好的 pytest 环境及已有测试。

模型每轮接收目标、当前计划、读过的文件、原始测试、候选问题、复现结果、当前代码版本及剩余预算，输出一个动作。工具返回观察后重新决策；控制器检查动作是否可执行，不替模型编排调查顺序。计划可多次更新，调整理由和历史会保存。

## 候选问题和证据

`record_candidate` 要求源码位置、可疑行为、具体预期、依据说明和已经读过的依据文件。行为依据可以来自项目文档、已有测试和明确的源码契约。控制器能验证文件读过、路径可访问，不能证明模型对自然语言的解释正确，因此保存 `basis_review=model_interpretation_not_independent_oracle`。

候选状态为 suspected、confirmed、rejected、inconclusive。confirmed 的严格含义是“按照引用的预期，在原始代码上观察到生成测试的断言不匹配”，不等于独立专家确认了业务缺陷。复现通过后不会自动判定仓库无问题，模型需要明确否定假设或说明证据不足。

首版最多八项候选，首次修改前完成候选登记；修复过程中只处理本轮已登记的候选。后续发现的新方向可以开新任务，避免同时改变调查基线和补丁范围。

## 生成与执行最小复现

`write_reproducer(candidate_id, code)` 接收带 `test_` 函数和非字面常量断言的 Python 测试。代码写入任务 `artifacts/reproducer-cN.py`，固定 SHA-256 后不可改写，网页可以下载。错误复现需要显式处置旧候选，再创建新候选，不能把预期改成当前结果来制造通过。

`run_reproducer` 将原始快照或当前开发副本复制到 `investigation/run-N/`，在临时副本中注入固定命名的测试文件，由现有 runner 以固定 pytest 命令执行。Agent 不能选择任意 shell。原有测试和开发副本不写入生成的文件，只有允许的源码补丁进入最终 diff。

首次运行使用原始快照，后续运行使用当前源码；结果绑定 revision、源码摘要和测试编号。全部执行共享测试次数、命令时间及取消控制。检测临时副本可见文件被测试改写时，不接受它作为有效证据；原工作副本摘要发生变化同样使证据失效。

缺依赖、收集失败、普通运行错误、跳过全部测试、输出上限、取消及超时都不能确认问题。pytest 断言失败且失败节点指向生成文件，才允许进入 confirmed。AST 解析只检查测试基本形态，不是代码安全隔离，也不能证明测试没有虚构预期；生成代码与仓库测试遵循相同执行信任边界。本地运行仅供可信代码，Docker 实机检查范围见 [评测记录](evaluation/README.md)。

## 修复与提交

自主检查模式的 `record_finding` 必须关联一个 confirmed 候选及其源码位置。编辑仍需计划、原始开发测试、已读源码和当前版本的假设。模型可以根据失败调整计划、继续阅读或撤销；工具不会替它决定补丁内容。

提交前需要非空源码补丁、当前版本原有测试通过，以及每个 confirmed 候选的同一复现对当前版本通过。revision 和源码摘要任一不匹配都必须重测。

最终验证器从原始快照构建干净副本并应用补丁，运行外置验收（如有）及回归，再在独立副本中重跑固定复现。生成复现单独列为 `generated_reproducers`，明确 `independent_oracle=false`；只有仓库外预先准备的验收才属于独立验收数据。任何复现失败都不能把补丁标成 passed。

## 无补丁结束和失败

`finish(reason=investigation_complete)` 要求有计划、读过文件、运行过原始测试、没有源码变更，并显式处置所有待验证候选。任务状态为 reviewed，界面显示“检查完成 · 未提交补丁”，交付调查范围、证据、未解决问题和未覆盖部分。confirmed 候选也可以留在无补丁报告中，供后续人工处理。

原始测试存在失败但未调查候选、环境故障、预算耗尽或存在未验证补丁时，不能冒充调查完成；按阻塞/预算状态结束并保存证据。没有确认问题的报告也不能证明仓库完全正确。

Schema 反馈只提供字段名、错误类型和不含输入值的校验说明，不保存供应商响应正文。格式错误作为事件展示，模型有机会依据具体错误修正参数，连续错误仍受原有终止机制限制。

## 复现和验证

自建样例为 `examples/investigation/repo`：原有两项测试通过，README 有明确行为约定，源码遗漏部分要求。`examples/investigation/acceptance` 是不提供给 Agent 的外置验收；`repository.json` 仅用于该样例，不加入三个脚本演示入口。它不是外部开源仓库或修复率评测。

```powershell
uv run repairlab run --profile .\examples\investigation\repository.json --task-kind inspect --mode model --backend local --allow-local
```

临时借用已经授权的配置验证时，可用 `scripts/smoke_investigation.py`，它不复制 `.env`，在退出时恢复进程环境变量。必须为并行运行选择独立 `REPAIRLAB_DATA_DIR`。浏览器验证脚本 `scripts/investigation_ui_qa.cjs` 使用实际完成的任务历史，不模拟模型决策。

测试重点包含原有测试通过但复现失败、错误假设被否定、环境/复现错误不能确认、测试不可改写、预算共享、证据版本失效、未验证补丁不能冒充无补丁完成、原有测试通过但最终复现失败拒收，以及完整修复与无补丁调查的持久化。
